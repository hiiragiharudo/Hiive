# Hiive 使用指南

> 面向：本项目作者（毕设答辩 / 日常开发 / 给导师演示）
>
> 所有命令均在 **Windows PowerShell** 下验证通过。

---

## 0. 先搞清楚这个项目是干什么的

一句话：**给 AI 渗透测试 Agent 做"技能调度"**。

现在的 AI 渗透工具都把技能（`SKILL.md`）的元数据**全部塞进提示词**。
技能一多就撑爆上下文（800 个技能 ≈ 80k token），而且技能会互相抢答
——你自己的语料里就记录了"5 个技能抢同一触发词、4 个自称总路由"。

Hiive 解决两件事：

| 问题 | Hiive 的做法 |
|---|---|
| 技能库太大，全量注入撑爆上下文 | **两阶段路由**：先用检索挑出 top-k，只把这 k 个技能注入上下文 |
| 技能互相抢答，同一输入走不同路线 | **技能仲裁**：把人工写的仲裁规则解析成可强制的约束 |

**它不是**一个漏洞扫描器，**也不打任何真实目标**。全部实验在离线模拟靶场里跑。

## 1. 三分钟跑起来（最简路径）

只想看效果，跑这一条：

```powershell
cd H:\Hiive\backend
..\.venv\Scripts\python.exe tools\run_lab.py
```

这会离线跑完整的 Agent 流程并打印结果，**不需要启动服务、不需要网络、不花钱**。
看到下面这些就说明一切正常：

```
★ 经验证的发现：  [critical] broken-access-control @ /admin/users ...
被拒绝的候选：    sql-injection @ /search  原因：响应体未包含 'SQL syntax'
技能贡献度（回溯统计）： ...
```

> 那段"被拒绝的候选"是**故意设计的**：靶场里根本没有 SQL 注入，
> 所以一个声称"有 SQL 注入"的技能必须被判为假阳性。这是本项目的核心卖点之一。

## 2. 四种使用方式

### 2.1 离线命令行工具（不启服务，最快）

全部在 `backend\tools\` 下，用同一个解释器运行：

| 命令 | 干什么 | 你要看什么 |
|---|---|---|
| `..\.venv\Scripts\python.exe tools\run_lab.py` | **Agent 全流程演示**（推荐先跑这个） | 经验证的发现、被拒绝的候选、技能贡献度、越界拦截 |
| `..\.venv\Scripts\python.exe tools\run_bench.py` | 路由质量基准的**消融对照** | R@1/R@3/R@5、MRR、弃权准确率、元数据节省 |
| `..\.venv\Scripts\python.exe tools\probe_routing.py` | 开发期探针 + 跨语言消融 | 中文/英文命中数对比、召回失败 vs 排序失败 |
| `..\.venv\Scripts\python.exe tools\generate_metadata.py` | 生成技能路由元数据 + 效果测量 | 覆盖率（0 → 125）、元数据层的边际贡献 |
| `..\.venv\Scripts\python.exe tools\mine_lexicon.py` | 从真实 SRC 报告挖掘中英术语对 | 读取文件数、挖掘出的术语对（**这条边际贡献为负，见报告**） |
| `..\.venv\Scripts\python.exe tools\smoke_api.py` | 对**运行中的服务**做端到端验证 | 需要先启动服务，见 2.2 |
| `..\.venv\Scripts\python.exe -m pytest tests -q` | 跑全部 205 项测试 | 全绿即正常 |

### 2.2 启动后端服务（答辩演示用）

```powershell
# 终端 A
cd H:\Hiive\backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

打开 **http://127.0.0.1:8000/docs** —— 这是自动生成的接口文档，
**22 个端点全部可以在这个页面上直接点击试跑**，不需要写任何代码。

答辩时如果想现场演示接口，这个页面比什么都方便：
展开 `POST /api/route` → 点 "Try it out" → 在 `query` 里填一句话 → Execute。

### 2.3 启动前端界面（演示观感最好）

```powershell
# 终端 B（保持终端 A 的服务的运行）
cd H:\Hiive\frontend
npm run dev
```

打开 **http://localhost:3000** ，四个页面：

| 页面 | 用来干什么 |
|---|---|
| **检索路由** | ★ 核心演示：输入任务描述 → 看召回了哪些技能、**为什么召回**（命中哪个字段、得分多少）、省了多少 token、**仲裁丢掉了哪些技能及原因**、适用哪些约束 |
| **Agent 执行** | ★ **挖洞结果在这里**：先选**目标**（离线模拟靶场 / sqli-labs / DVWA / Pikachu），再运行任务 → 看**经验证的发现（带证据链）**、**被拒绝的候选（假阳性）**、逐步执行留痕、技能贡献度回溯、攻击图、越界拦截 |
| 技能库 | 160 个条目的健康度、过滤检索、点进详情看依赖闭包与正文 |
| **规则与仲裁** | 12 条约束规则、冲突裁决表、**技能仲裁表全文**、**仲裁强制执行演示按钮** |
| 评测看板 | 一键复现论文里的各组对照实验、失效明细（区分"召回失败"与"排序失败"） |

### 2.3.1 打真实靶场（主打功能）

**前提**：靶场需先就绪（见 `docs/靶场环境搭建.md`）。

```powershell
# 1. 启动靶场（XAMPP 的 MariaDB 3307 + Apache 80）
.venv\Scripts\python.exe eval\ranges\setup_ranges.py     # 初始化（首次）
# 或用图形界面：H:\XAMPP\xampp-control.exe 启动 Apache 与 MySQL

# 2. 启动后端与前端（见上面 2.2 / 2.3）

# 3. 浏览器打开 http://localhost:3000/agent
#    → 在「选择目标」里点 sqli-labs / DVWA / Pikachu
#    → 点预置任务即可
```

命令行也可直接打：

```powershell
cd backend
..\.venv\Scripts\python.exe tools\run_range.py                     # 列出靶场
..\.venv\Scripts\python.exe tools\run_range.py --range sqli-labs    # 打 sqli-labs
..\.venv\Scripts\python.exe tools\run_range.py --range dvwa         # 打 DVWA（自动登录）
```

**DVWA 会自动登录**并把安全级别切到 `low`——这两步由
`eval/ranges/profiles.json` 的 `login` 声明式配置完成，不需要手工操作。

> **如果前端报"未连接"**：检查终端 A 的服务是否还在跑，以及端口是不是 8000。
> 前端通过 `frontend/.env.local` 里的 `NEXT_PUBLIC_API_BASE` 找后端（默认 `http://127.0.0.1:8000`）。

### 2.4 盘点本机技能语料

```powershell
cd H:\Hiive
python scripts\inventory_skills.py
```

扫描本机技能语料，生成 `docs/技能资产清单.md` 与 `data/skill_catalog.json`。
（这两个文件被 `.gitignore` 排除，因为含本机绝对路径与第三方付费知识库正文。）

## 3. 演示脚本（照着念就行）

答辩或给导师演示时，按这个顺序最顺：

**第 1 步 · 讲问题**（30 秒）
打开 http://localhost:3000 ，在检索路由页输入：
```
挖一下 XX 公司，做授权渗透测试
```
最上面会看到「检索返回 5 个，仲裁后保留 2 个」，下面列出**每个被丢弃技能的原因**。
念一句：**"技能可以在自己的描述里自称总路由，规范对此没有约束，
所以同一句话可能走 5 条不同路线。这是行为不一致，不是检索不准。"**

**第 2 步 · 讲方案**（30 秒）
把检索路由页往下拉，指「上下文成本对比」那张双层条形图：
元数据项 **O(N) → O(k)**，实测这个查询省了 **97.5%**。

**第 3 步 · 讲验证**（1 分钟）
切到「规则与仲裁」页，点一个仲裁演示按钮 → 实时看到丢弃过程。
再切到「评测看板」页，点「② 仅查询侧扩展」→ 出现 R@5 84.2%。
念一句：**"这是 86 条标注基准上的数字，配置之间的差异是可复现的。"**

**第 4 步 · 讲效果**（1 分钟）
切到「Agent 执行」页，点「正常流程」：
念：**"6 步执行，5 个经验证的发现，每个都带证据链。"**
再点「假阳性抑制」：
念：**"技能声称有问题不等于真有问题——只有通过确定性验证判据的才算发现。
不靠提示模型不要误报，靠架构拦住。"**
最后点「越界拦截」（会把授权主机故意填错）：
念：**"越界请求在工具层与靶场层各校验一次，累计拦截达阈值即熔断，
不持续冲击被拦目标。"**

## 4. 常见问题

**Q：跑的时候会不会真的去打什么东西？**
不会。靶场是 `backend/app/agent/target.py` 里的**进程内模拟**，
不监听端口、无网络 IO、不含可用 exploit。全部 205 项测试也是离线的。

**Q：需要 API Key / 花钱吗？**
不需要。路由评测、离线路由、Agent 演示全部零 API 调用。
只有将来做"端到端跑真实靶场"（DVWA/Juice Shop）才需要调用 LLM。

**Q：为什么有些技能显示"跳过（skipped_no_plan）"？**
因为语料里的第三方技能是**方法论文本**，本来就不该被自动执行。
引擎对它们如实记录"跳过"，而不是假装执行过。

**Q：`tools/run_bench.py` 里"弃权准确率 0.000"是不是坏了？**
不是，这是**如实报告的未解决问题**。RRF 融合只用排名、丢弃分数大小，
其得分恒等于 `1/(k+rank)`，与匹配强度无关，所以基于得分的阈值弃权
**在原理上不可行**。改用 IDF 加权覆盖率后信号分离度仍差（两组区间重叠 0.318）。
这条已写入论文局限，**不声称解决**。

**Q：数据存在哪？**
目前**没有数据库**。任务与留痕随响应返回，不落库。
`tasks`/`task_skills` 表的数据模型已在设计文档 §9 里规划，属未完成工作。

**Q：想换一批技能语料怎么办？**
设环境变量覆盖默认路径（多个路径用 `;` 分隔）：

```powershell
$env:HIIVE_SKILL_ROOTS = "D:\my-skills"
$env:HIIVE_KB_ROOTS    = "D:\my-kb"
$env:HIIVE_RULES_ROOTS = "D:\my-rules"
..\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

或服务起来后调 `POST /api/skills/reload` 重建索引。

## 6. 改代码前的两个提醒

1. **改语料结构要重建索引**：`skill_roots` / `tokenizer` / `vector_kind` /
   `scoring` / `enrich_triggers` 属于**建索引时**参数，改完要 `POST /api/skills/reload`。
   查询时参数（`top_k` / `expand_query` / `channels` / `min_coverage`）可以按请求覆盖。
   这个区分在 `GET /api/config` 里会返回给前端——**别把两类参数搞混，否则会出现"改了没反应"**。

2. **不要自动改写别人的 `SKILL.md`**：本项目所有加工都产出**覆盖层**
   （`data/skill_metadata.json`），原始文件字节不变。有测试守着这条
   （`test_overlay_does_not_modify_source_files`）。
