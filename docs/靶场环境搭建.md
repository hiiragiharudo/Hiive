# 靶场环境搭建（sqli-labs / DVWA / Pikachu）

> 本机环境：**XAMPP**（Apache 2.4.58 + PHP 8.2.12 + MariaDB 10.4.32），位于 `H:\XAMPP`
>
> 三个靶场都是 PHP 应用，跑在 XAMPP 上，**不需要 Docker**。

---

## 1. 本机的两个特殊处理（务必先读）

### 1.1 端口冲突：3306 已被占用

本机 **3306 被一个独立安装的 MySQL 8.0 占用**（`C:\Program Files\MySQL\MySQL Server 8.0`），
不是 XAMPP 自带的 MariaDB。

因此 XAMPP 的 MariaDB 改走 **3307**：

- `H:\XAMPP\mysql\bin\my.ini`：`[client]` 与 `[mysqld]` 两处的 `port` 改为 `3307`
- `H:\XAMPP\php\php.ini`：`mysqli.default_port=3307`

这样 XAMPP 这一套完全自包含，**不需要知道那个 MySQL 8.0 的密码**，两者互不干扰。

### 1.2 必须重启 Apache

**改完 `php.ini` 必须重启 Apache 才生效。** 这一点踩过坑：
先启动 Apache 再改 `php.ini`，Apache 仍用旧配置连 3306，
于是 Pikachu / DVWA 都连库失败，而**页面不报错、只是静默不工作**。

### 1.3 php.ini 的三处改动

| 项 | 值 | 原因 |
|---|---|---|
| `mysqli.default_port` | `3307` | 让所有靶场自动连到 XAMPP 的 MariaDB |
| `extension=gd` | 启用 | DVWA 的 setup 检查要求 |
| `allow_url_include` | `On` | DVWA 的 File Inclusion 模块演示 RFI 需要（**仅本机靶场环境**） |

> 原始配置已备份到 `.reference/xampp-config-backup-<时间戳>/`。

## 2. 三个靶场

| 靶场 | 目录 | 数据库 | 版本来源 |
|---|---|---|---|
| sqli-labs | `htdocs/sqli-labs` | `security` | [`skyblueee/sqli-labs-php7`](https://github.com/skyblueee/sqli-labs-php7) |
| DVWA | `htdocs/DVWA` | `dvwa` | [`digininja/DVWA`](https://github.com/digininja/DVWA) |
| Pikachu | `htdocs/pikachu` | `pikachu` | [`zhuifengshaonianhanlu/pikachu`](https://github.com/zhuifengshaonianhanlu/pikachu) |

### 2.1 为什么 sqli-labs 用的是 fork

原版 [`Audi-1/sqli-labs`](https://github.com/Audi-1/sqli-labs) 使用 **`mysql_*` 函数**，
这套 API 在 **PHP 7.0 就被移除了**，在 PHP 8.2 上直接致命错误。
`skyblueee/sqli-labs-php7` 是社区维护的 mysqli 适配版（244 star），可直接跑。

### 2.2 三个靶场的初始化方式各不相同

| 靶场 | 初始化 |
|---|---|
| sqli-labs | 导入仓库自带 `sql-lab.sql` |
| Pikachu | POST `install.php`（自建库建表 + 默认数据） |
| **DVWA** | POST `setup.php`，**必须先取 CSRF token** |

> ⚠️ **DVWA 的 `setup.php` 与 `login.php` 都带 CSRF token**（`checkToken()`）。
> 不带 token 直接 POST 会**返回 200 但什么都不做**——静默失败。
> 这是自动化初始化最常见的坑。

### 2.3 DVWA 的安全级别必须是 low

DVWA 默认 `default_security_level` 是 `impossible`，**该级别下各模块不可利用**，
靶场就失去意义。本项目在 `config/config.inc.php` 里设为 `low`。
页面左侧「DVWA Security」可随时切换。

## 4. 漏洞真实性验证（区分「能访问」与「有漏洞」）

```powershell
.venv\Scripts\python.exe eval\ranges\probe_ranges.py
```

**`setup_ranges.py` 只证明服务在跑，`probe_ranges.py` 证明漏洞在。**

实测输出：

```
[sqli-labs] Less-1 字符型注入（差分法，不依赖报错显示）
  ✓ 基线 id=1 → 回显登录名 'Dumb'
  ✓ id=1' → 回显变化（''），说明引号进入了 SQL
  ✓ id=1'-- - → 回显恢复（'Dumb'），注释符生效
  ✓ UNION SELECT 1,2,3 → 回显位 2（可利用）

[Pikachu]  ✓ 字符型注入   ✓ 反射型 XSS 探针原样回显
[DVWA]     ✓ 登录（带 CSRF token）  ✓ 安全级别 = low
           ✓ SQLi 模块 id=1 → 'admin admin'；id=1' → ''（回显变化）
```

### 4.1 两个已验证的判据陷阱（写技能判据时必须知道）

| 陷阱 | 说明 |
|---|---|
| **sqli-labs 不能看报错** | 它的 `sql-connect.php` 里有 `@error_reporting(0)`，SQL 报错被有意屏蔽。用"是否出现报错"当判据会**假阴性**。改用**差分法**：正常 → 破坏 → 注释修复 → UNION 回显。 |
| **Pikachu 页面含大量 JS 资源** | 页面里本来就有很多含 `error` 字样的脚本引用，宽泛正则匹配会**假阳性**。判据要精确到 `SQL syntax` / `mysql_fetch` 这类数据库报错特征。 |

> 这两条是本项目在编写验证判据时实际踩到的，
> 也说明「验证判据本身也需要被验证」——与 `arXiv:2608.09567` 的发现一致。

## 5. 手动启动 / 停止

```powershell
# MySQL（3307）
H:\XAMPP\mysql\bin\mysqld.exe --defaults-file="H:\XAMPP\mysql\bin\my.ini" --console

# Apache（80）
H:\XAMPP\apache\bin\httpd.exe -f "H:\XAMPP\apache\conf\httpd.conf"
```

或用图形界面：`H:\XAMPP\xampp-control.exe`。

访问入口：

| 靶场 | URL |
|---|---|
| sqli-labs | http://localhost/sqli-labs/ |
| DVWA | http://localhost/DVWA/ （`admin` / `password`） |
| Pikachu | http://localhost/pikachu/ （`admin` / `123456`） |
